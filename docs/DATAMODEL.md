# Data model

What the prototype knows, where each fact lives, and how the facts are joined.
The app reads static JSON under `data/`, fetched once at boot; `store.js` adds
indexes and derived figures on top and never writes anything back. Seven of
the files are generated by `tools/generate-portfolio.js`, four are written by
hand — see `tools/README.md` for the generator and `ARCHITECTURE.md › Data` for
the current fixture counts.

The tenancy agreements — the Mietverträge tab — are a second, separate model
under `data/tenancy/`; its files and fields are described in `tools/README.md`.

## Entities

```
meta.organisations ──1:n──▶ people.organisation
people ────────────1:n──▶ projects.leadId          projects.organisation = people[leadId].organisation (joined)
meta.portfolios ───1:n──▶ projects.portfolio
phases.eppm ───────1:n──▶ projects.phase · projects.bars[].phase · milestones.items[].subPhase
milestones.catalog 1:n──▶ milestones.items.code
projects ──────────1:n──▶ milestones.items.projectId · changes.projectId
meta.quarters[i] ───────▶ index i of every per-quarter array: demand, baseLoad, gross, absence, external
```

Three rules hold the model together:

- **A person belongs to an organisation; a project does not.** The unit is a
  fact about the person. A project reaches its unit through its assignee, and
  the join is one getter in `store.js`, so a project without an assignee has no
  unit and a re-assignment moves the project with the person.
- **Time is one window.** `meta.quarters` lists the forty quarters the
  prototype covers, and every per-quarter array is indexed by position in that
  list. Index 0 is the first quarter of the window, which is also the current
  one. A quarter is named by an id of the form `2026Q3`.
- **A pensum is a share of a full position.** Every load figure — a project's
  demand, a person's booked load, the office's capacity — is a percentage of
  one full-time position, so `100` is one FTE and the figures add up across
  people and projects. The unit switch in the app divides by 100 for display.

## Files

### `meta.json` — the frame

| Field | Meaning |
| --- | --- |
| `org` | `name`, `division`, `app`, `unit`: the letterhead — the header prints office, division and application on three lines |
| `user` | the signed-in person: `personId`, `name`, `initials`, `role`, `signedIn` |
| `today`, `todayLabel`, `todayQuarter` | the fixed «now» of the fixtures, ISO date, display date, quarter id |
| `asOf`, `lastVisit`, `version` | the data stamp in the footer, the last visit for the notification badge, the version line |
| `quarters[]` | the window: `{ id, label, short, year }`, e.g. `2026Q3`, `Q3/2026`, `Q3`, `2026` |
| `portfolios[]` | the Teilportfolios: `{ id, label }` |
| `organisations[]` | the six units: `{ id, label, short, projectShare }` — `PPE I`, `PM Inland II` are the short forms the grid columns use; `projectShare` is the per cent of a contract the unit's people may spend on projects |
| `settings` | the office's rules that are not a unit's: `smallProjectMio`, the credit in Mio. CHF up to which a project counts as small |
| `footerLinks[]`, `prototypeNotice` | chrome |

Only `quarters` is generated; the rest is the generator's own constant table,
written out so the app has a single source.

### `phases.json` — the ePPM chain (hand-written)

`eppm[]` is the ordered list of Teilphasen every project runs through:
`Vorstudien`, `22 Auswahlverfahren`, `31 Vorprojekt`, `32 Bauprojekt`,
`53 Inbetriebnahme`, `61 Betrieb`, as `{ id, label }`. The id is the SIA
number, or `Vorstudien` for the BBL-specific first step. The order in the file
is the order of the chain; `eppmRank()` in `store.js` sorts by it.

### `people.json` — the roster

| Field | Meaning |
| --- | --- |
| `id` | stable slug, the key `projects.leadId` points at |
| `name`, `initials`, `shortName` | display forms, precomputed |
| `role` | `Projektleitung` or `Bauleitung` |
| `employment` | the contract, in % of a full position |
| `organisation` | id in `meta.organisations` |
| `projectShare` | optional: the person's own project share in %, where it differs from the unit's. No fixture carries one yet |
| `baseLoad[]` | booked pensum per quarter, in % of a full position: the sum of the demand of the projects the person carries |

`baseLoad` is the generator's roll-up; the app reads it through
`personLoad()`, which adds the delta of any unsaved edit, and turns it into a
share of the person's project capacity through `personUtilisation()`.

Nobody has their whole contract free for projects. `projectShare(person)`
reads the person's own share or, failing that, the unit's, and
`projectCapacity(person)` is `employment × projectShare / 100` — an 80 %
contract in a unit that keeps 20 % back carries 64 pensum points of projects.
That is the ceiling a person's load is measured against.

### `capacity.json` — the office as a whole

`gross[]`, `absence[]` and `external[]` are per-quarter arrays in % of a full
position for the whole unit; `net = gross − absence` is computed. `labels`
names the rows of the totals block under the planning grid. Capacity is
modelled at the level of the office, not per person: a person's ceiling is
their project capacity (see `people.json`), and absences are not per person in
this prototype. `gross` is still the sum of the contracts, without the project
share taken off — see the open questions in `DECISIONS.md`.
`quarters` in this file is a leftover of the earlier eight-quarter window and
is not read; the arrays are indexed by `meta.quarters`.

### `projects.json` — the portfolio

| Field | Meaning |
| --- | --- |
| `id`, `number` | `pr51` and the four-digit display number `0051` |
| `title`, `location`, `kind` | «Ort, Strasse, Massnahme» and its parts |
| `phase` | the current Teilphase, an id in `phases.eppm` |
| `leadId` | the assignee, a `people.id`, or `null` for «nicht zugewiesen» |
| `portfolio` | id in `meta.portfolios` |
| `priority` | `hoch`, `mittel`, `tief` |
| `credit`, `creditLabel` | the credit in Mio. CHF, or `null` and «offen» before the Baukredit is released |
| `preCredit` | whether the project is still before the Baukredit release; its demand is reported separately in the totals |
| `target` | the Soll-Pensum in % |
| `demand[]` | the planned pensum per quarter, in % of a full position |
| `bars[]` | the phases that touch the window: `{ phase, from, to, label }`, in quarter offsets from index 0; `from` is negative for a phase that began before the window |

A project has no `organisation` field. `store.js` defines it as a getter on
every project at load time, reading the assignee's unit, so the column, the
filter, the grouping, the dashboard cards and the export all read
`p.organisation` and see the same answer.

### `milestones.json` — the gates

`catalog[]` names the six Hauptphasen as `{ code, name, short }` — `1
Strategische Planung` … `6 Bewirtschaftung`. In the interface they are the
milestones: each is the gate that closes a Teilphase.

`items[]` is one gate per project and Hauptphase:

| Field | Meaning |
| --- | --- |
| `id` | `ms-51-4`: project number and gate code |
| `code` | the Hauptphase, a key in `catalog` |
| `projectId`, `subPhase` | the project, and the Teilphase this gate closes |
| `plan`, `planDate` | the planned quarter id and the planned date, shortly before the phase ends |
| `forecast`, `forecastDate` | the current forecast |
| `status`, `statusLabel` | `ok`, `late` or `pending`, and its German label |
| `impact` | one line on what a slip means |

The bar plan places a gate at `planDate`; the notifications list the late
ones; the dashboard counts the gates whose `plan` is the current quarter.

### `changes.json` — the history

A flat list, newest first: `{ id, date, dateLabel, actor, projectId,
projectLabel, field, change, value, onLanding }`. `value` is the before-after
text («30 % → 35 %»), `onLanding` marks the entries the landing page's
notification badge counts against `meta.lastVisit`. Nothing in the app
appends to it: an edit in the session is a transient override, not a history
entry.

### `dashboard.json` — what is not derived

The card menu's labels and the one card whose figures are not computed from
the projects: `creditByYear`, credit by year of realisation, as
`{ label, value, valueLabel, note }` rows. Every other dashboard card is
derived from `projects.json` at render time and follows the filters; this one
does not.

### Hand-written files

- `i18n.json` — `languages` and `terms`: the German string is the key and the
  fallback, each entry carries `en`, `fr`, `it`.
- `print.json` — the letterhead, legend and notes of the printed report.
- `openapi.json` — the API the prototype would talk to. Its schemas are the
  richer model the office will need — `Allocation` and `Target` per person and
  project, `Absence` per person, a `PersonCapacity` — which the fixtures flatten
  into `demand[]`, `baseLoad[]` and the office-level `capacity.json`.

## Derived in the app

`store.js` builds these once at load and again on every edit; nothing here is
in a file.

| Derived | From |
| --- | --- |
| `peopleById`, `projectsById`, `portfoliosById`, `organisationsById`, `quarterIndex` | the lists above |
| `project.organisation` | `peopleById[leadId].organisation`, as a getter |
| `cellValue(p, q)`, `projectDemand(p)` | `demand[]` with the session's overrides (`'projectId:q' → value`) applied |
| `projectShare(person)`, `projectCapacity(person)` | the person's share or the unit's; `employment × share / 100` |
| `personLoad(id, q)`, `personUtilisation(id, q)` | `baseLoad[]` plus the overrides' delta; divided by `projectCapacity` |
| `totals(list)` | per quarter: `demand`, `preCredit`, `external`, `net`, `utilisation = demand / net`, `free = net − demand` |
| `filteredProjects()`, `groupProjects()`, `groupPeople()` | the state's search, filters and grouping |
| `periods()` | the visible columns: quarters, or years and months folded from them, at the current offset |
| `kpis()` | projects in scope, credit total, pensum total, gates this quarter |

## Conventions

- Ids are stable slugs (`sonja`, `pr51`, `ppe-1`, `verwaltung`), so a shared
  link survives a renaming.
- Dates are ISO `YYYY-MM-DD`; where a display form is needed the file carries
  it precomputed (`dateLabel`, `todayLabel`, `creditLabel`).
- Credits are in Mio. CHF as numbers, `null` where none is released.
- Labels are German in the files; the interface translates through `t()`.
- The generator is deterministic and rewrites all seven generated files in
  one run; the story projects in `tools/seed/` are overlaid on the generated
  portfolio by id.
